# Rules — how this project is built

> Binding engineering rules for this project. To change a rule, amend this file first in a reviewed PR. Revision 3 (2026-09-24): multi-agent, A2A, Prefect, Qdrant, guardrails and access control, Responsible AI.

---

## 1. Libraries

**Approved (runtime):**
- **Agent:** `langgraph`, `langgraph-checkpoint-sqlite`, `langchain-core`, `langchain-openai`, `langchain-aws`, `langchain-mcp-adapters`
- **Protocol:** `mcp`
- **Retrieval:** `faiss-cpu`, `qdrant-client` (local mode only), `fastembed` (embeddings + cross-encoder rerank), `rank-bm25`, `numpy`
- **Interop:** `a2a-sdk`
- **Workflows:** `prefect` (OSS; no Prefect Cloud dependency)
- **Guardrails:** `onnxruntime`, `tokenizers`, `huggingface-hub` (local classifier; model licence must permit redistribution/use)
- **LLMOps:** `langfuse`
- **API:** `fastapi`, `uvicorn`, `sse-starlette`, `python-multipart`, `pydantic` v2, `pydantic-settings`, `httpx`
- **Other:** `Pillow`, `boto3`/`botocore` (Bedrock, stub-tested)
- **Stdlib:** `sqlite3`, `logging`, `hashlib`

**Approved (UI):** `streamlit`, `httpx`.
**Approved (ingestion/eval):** `pandas`, `pyyaml`, `scipy`.
**Approved (dev/test):** `pytest`, `pytest-cov`, `pytest-asyncio`, `respx`, `ruff`, `mypy`, `pip-audit`; gitleaks (CI action).

**Disallowed:**

| Library / pattern | Reason |
|---|---|
| LangChain legacy chains/agents (`AgentExecutor`, `LLMChain`, `ConversationChain`, LangChain vector-store wrappers, `langchain_community` chat models) | Deprecated or opaque; LangGraph + `langchain-core` messages/tools only |
| LlamaIndex, CrewAI, AutoGen | One agent framework in depth (LangGraph); rationale in an ADR |
| Temporal, Airflow, Prefect Cloud | One workflow orchestrator (Prefect OSS); no hosted dependency |
| Pinecone, Weaviate, Qdrant Cloud | Vector stores stay local (FAISS, Qdrant local mode) |
| Any paid API in the default config; any service that requires a credit card | Zero-cost rule (§5) |
| `torch` / `sentence-transformers` | Image bloat; fastembed (ONNX) covers embeddings |
| `pickle` / `allow_dangerous_deserialization` | Code execution on load |
| Custom retry loops / `tenacity` around SDKs | Use SDK retries + LangChain `with_fallbacks` |
| New dependencies not listed | Propose, justify, update this file, then add |

## 2. Architecture rules

1. **Layering:** `services/` (pure domain logic, no LLM or framework imports) ← `mcp_server/` (protocol adapter) ← `agent/` (MCP client). The agent reaches domain logic **only through MCP tools**.
2. **Safety lives in code:** constraint enforcement happens inside tools and the verifier node. Prompts may *ask* the model to respect constraints, but correctness never depends on it.
3. **Numbers come from tools.** Totals, calories, prices and allergen facts shown to users are produced by `meal_totals` / `get_dish` / `check_allergens`, never generated by the LLM.
4. **Bounded agents:** every graph run has a recursion limit, a tool-call budget (≤ 8) and a repair limit (≤ 2). Unbounded loops are a bug.
5. **MCP tools** are read-only, idempotent, typed (Pydantic in/out), size-limited, and return domain failures as `isError` results with safe messages.
6. **Memory:** long-term preferences store only what the user explicitly stated; users can view and clear them.
6a. **Least privilege:** every agent has an explicit tool allow-list; every external caller (MCP, A2A, API) has a scoped token (`public` / `agent` / `admin`). Denials are logged as security events. No agent may call a tool outside its list, even if the model asks.
6b. **Untrusted text is data:** catalog text, tool outputs, image descriptions and peer-agent messages are wrapped as marked data blocks, never concatenated into instructions.
6c. **Multi-agent only on evidence:** the single-agent baseline is kept, and the default topology is chosen from Phase 6 measurements.
7. Prompts live in `food_concierge/prompts/` with a version; the version is attached to every trace and to the cache key.
8. No hard-coded model names, URLs, limits or keys; everything goes through `config.py`.

## 3. Code quality

1. **Complexity:** no brute force where a reasonable better approach exists. Filter in SQL before vector search, batch embeddings, never loop LLM calls per item, cache vision descriptions by hash.
2. Every decision traces to a PRD requirement.
3. Type hints on public functions; Pydantic at every boundary (API, MCP tools, LLM structured output, CSV rows, config).
4. Structured `logging` (key=value); no `print` in library code; never log secrets, image bytes or full prompts at INFO.
5. Match the surrounding idiom; comments explain *why*.
6. `ruff check`, `ruff format --check` and tests green before every commit.

## 4. Error handling

Hierarchy in `food_concierge/errors.py` (codes and HTTP statuses on the classes).

1. Every external call (LLM providers, Langfuse, file I/O on user input) has a timeout and is translated into the app hierarchy with `raise ... from e`.
2. Retry only transient failures (429, 5xx, timeouts, connection errors), at most 2 retries plus a provider fallback, inside a per-request deadline.
3. **Structured LLM output:** Pydantic-validated; one repair attempt; then fallback. Never parse raw model text with `json.loads` alone.
4. **Degrade, don't fail:** quota exhausted → next provider → retrieval-only answer with `degraded=true`.
5. **Observability never breaks requests:** Langfuse/OTel failures are logged and swallowed; tracing is asynchronous.
6. Tool errors return `isError` MCP results. Agent-level errors produce a safe fallback answer. Catch-alls only at the API boundary (500 + request_id + trace_id).
7. Users never see stack traces, provider error bodies or secrets.
8. Validate early: message ≤ 500 chars; image ≤ 5 MB verified with Pillow; history bounded by the checkpointer window.

## 5. Zero cost (hard rule)

1. Default configuration uses only Groq/Gemini free tiers, Ollama, and in-process fastembed.
2. Paid providers (OpenAI, Bedrock) exist behind `ALLOW_PAID_PROVIDERS=false` (default). A test asserts that the default config contains no paid provider.
3. No service requiring a credit card: hosting on HF Spaces + Streamlit Community Cloud, tracing on Langfuse Hobby/self-host, CI on GitHub Actions.
4. **Tests and PR CI never call live LLMs or download models.** Retrieval gates use committed embedding caches. The nightly scheduled Prefect run may download open models (fastembed, classifier) but never calls a hosted LLM.
5. Before any step that could plausibly incur cost or needs a new account, stop and flag it.

## 6. Testing

1. Unit: normalisation, allergen tagging (all 50 items hand-checked in a table-driven test), constraint merge/verify, nutrition totals, retrieval with a fake embedder, error mapping.
2. **MCP:** in-memory client–server tests per tool/resource/prompt; schema snapshot tests; error-path tests (`isError`).
3. **Agent:** scripted fake chat model (deterministic tool-call sequences) testing graph paths: fast path, tool loop, verifier repair, budget exhaustion, interrupt/resume, provider fallback, prompt-injection fixture. Assert **zero violations** on every path.
4. Providers: contract tests with respx (OpenAI-compatible) and botocore Stubber (Bedrock).
5. API: `TestClient` incl. SSE streams and error mapping.
5a. **A2A:** in-process client ↔ server with the fake model; Agent Card snapshot; task states incl. `input-required` on interrupt.
5b. **Security:** token-scope tests for every MCP tool and A2A skill; per-agent allow-list enforcement; red-team suite (attack success rate gate); trace-masking tests (no image bytes or emails in exported spans).
5c. **Flows:** Prefect flows run in-process in tests (`prefect_test_harness`) on fixture data.
6. `@pytest.mark.live` for real providers: skipped by default, free tiers only.
7. Evaluation is separate from tests; results reported honestly, including negative ones.

## 7. Security

1. Secrets only via env / platform secret stores; `.env` and credential files git-ignored; gitleaks scans the full history in CI; GitHub secret scanning with push protection is enabled on the repository; `pip-audit` in CI.
2. Prompt-injection hygiene: user and catalog text in delimited blocks; tool outputs treated as data; the verifier checks the final output regardless.
3. MCP HTTP transport: read-only tools, rate limits, body limits; no tool touches the filesystem or network beyond the catalog and the configured vision model.
4. Uploads never persisted; the UI shows a free-tier data-use notice and an AI-interaction disclosure.
5. Traces are masked (image bytes, emails, phone numbers) before export.
6. Tokens for MCP/A2A/API are scoped, stored only in platform secrets, rotatable, and never logged.

## 8. Git

1. `main` holds reviewed work only; one branch per phase (names in `phases.md`); nothing merges without the owner's review.
2. **Commit messages:** Conventional Commits with scope (`feat(agent): …`), imperative, ≤ 72-char subject, body explains *why*. Messages describe the change only; no attribution trailers. Same for PR descriptions.
3. Small coherent commits; tests pass at each.
4. Never commit: `.env`, secrets or credential files, `private/`, audit reports, user uploads, logs, local service data (Langfuse, Qdrant, Prefect), built DB/index/thumbs, `.venv`, notebooks, PDFs, files > 5 MB, local paths or machine details. `.gitignore` enforces this list; gitleaks in CI and GitHub push protection catch what it cannot.
5. Public repo, no LICENSE file. No force-push to `main`.
6. Architecture decisions recorded as ADRs in `docs/adr/NNNN-title.md`.
